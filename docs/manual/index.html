GroovixBox Manual

A pad-based step sequencer with 8×8 RGB pads, eight function buttons, eight track buttons, nine faders and a mixer of eight strips. This manual covers every mode, button and page gesture, plus the keyboard mapping of the Linux simulator.

  • 32steps per pattern

While a page gesture is held, the buttons it uses stop doing their usual job and show the pages instead. B1 won’t pick a track while SHIFT is held, for example — it goes to track page 1.

Page panel

A third surface, and optional: a 5×8 grid of pads that does nothing but show which page of each kind is open and switch to another — one row a kind, one pad a page. It is an indicator and a switcher, never a second sequencer grid: it plays no notes and edits nothing, which is why five rows are enough where the main grid needs eight. An Akai APC Key 25 is this panel in hardware and is picked up automatically.

Everywhere else, page position is something you hold a modifier to see — SHIFT, or R2 in Preset mode. The panel shows all four kinds at once, all the time, which is the whole reason it exists.

RowPages
1 (top)Step pages — the 8 pages of 32 steps, as SHIFT + the top pad row picks them.
2Track pages — tracks 1–8 … 57–64, which B1–B8 then select.
3Project pages.
4Preset voice windows — all eight blocks of 512 voices, a pad each.
5 (bottom)Preset pages — the eight pages of the window picked on the row above.

Rows 4 and 5 are a pair. A window holds exactly eight preset pages, so window over pages reads like a row of tabs over what the open tab shows: pick a window on one row, a page of it on the next. The first kinds hang from the top and that pair is anchored to the bottom, so a device with more rows than the panel needs leaves the ones in between spare, dark and silent — an APC mini has three of those, and the Key 25 has none.

Each row lights the way the slot maps do: green for the page on screen, blue for a page holding something, dark for a page that doesn’t exist in this build. Tapping a pad goes to that page of that kind.

  • Its sixth side button is left unused, and on purpose: it is the one button on the device with no LED, and a mode button that cannot say whether its mode is open is worse than no button at all.

MIDI CC from the faders and knobs

Every fader and knob can send a MIDI CC, on the channel and port of the track it belongs to: the strip’s track on the current track page, or the selected track for the two master faders.

  • Moving a control sends it. The positions a surface reports when it starts are only recorded, so nothing is sent until you move something.
  • A CC is sent only when its value changes, so a slow move sends at most 128 messages over the whole travel.
  • Defaults: the mixer’s faders send Volume (CC 7), its knob rows Cutoff (74), Resonance (71) and Pan (10, centred), and the faders under the pads send Expression (CC 11). The two master faders send nothing.
  • The tempo is set with pads, not a fader — +10 and −10 beside +1 and −1 on the bottom row of Global settings — so every fader sends its CC in every mode.

The config file

Assignments are read from a text file, controls.conf. Without one the defaults above apply. The same file also says which MIDI device the ports go out of, so a rig is described in one place.

Where it is read from. The config directory, /mnt/usb1/config unless you say otherwise — the USB stick in a built rig. Projects go beside it in /mnt/usb1/data. The two are separate so a rig's settings can sit in /etc, beside your dotfiles or on read-only media while projects churn somewhere writable.

GivenReads
nothing/mnt/usb1/config/controls.conf, quietly falling back to the defaults if it isn't there
--config DIRDIR/controls.conf, and DIR/instruments.conf with it
--controls FILEexactly that file, whatever the directories say

Naming a place and finding nothing there is reported as an error, since you asked for it; a rig that names no place and has no file has simply never made one.

midiout     = MIDI4x4     # which interface P1..P8 go out of
p3          = Digitone MIDI 1   # or give one port a device of its own
mixfaderrow = 7           # all eight mixer faders: Volume
knobrow3    = 10, center  # the third knob row: Pan, centred
knob3.1     = 91          # just strip 1's third knob: reverb send
fader2      = 11          # a fader under the pads: Expression
master      = off         # sends nothing

Where the ports go. With nothing said, the first MIDI interface found is wired up in order, which is right for most rigs. midiout names the interface when there is more than one. p1–p8 go further and give a port a device port of its own — the way to put a USB synth on a port by itself. Write the name a port listing prints, copied as it stands:

LineWires that port to
p3 = MIDI4x4 Midi Out 2that port, named as the listing prints it
p3 = Digitonethat device, its first input
p3 = MIDI4x4:2its second input, counting the inputs it offers
p3 = Digitone:MIDI 1the input whose name contains that, on that device

Everything matches on part of the name and ignores case, so digitone finds “Elektron Digitone”. The first form is the one to reach for: it is a line off the screen, and it needs no counting. The two with a colon are for when a port's own name isn't enough — a cheap interface that calls its sockets MIDI 1 and MIDI 2 with no maker's name in them, where Digitone:MIDI 1 says which device's MIDI 1 you meant.

Once any p line is there, those ports are wired to exactly what they name and the rest are left alone for aconnect — the devices page shows which found something.

Finding the names

aconnect -o lists everything you can send MIDI to. The quoted name after client is what midiout and the p lines match, and the indented lines under it are that device's inputs:

client 32: 'MIDI Mix' [type=kernel,card=4]

    0 'MIDI4x4 Midi Out 1'                     <- its 1st input

Copy the quoted name. Everything between the quotes is what to write, and nothing else on the line matters:

Line in the listingWrite
0 'MIDI4x4 Midi Out 1'p1 = MIDI4x4 Midi Out 1
1 'MIDI4x4 Midi Out 2'p2 = MIDI4x4 Midi Out 2
client 40: 'MIDI4x4', all four inputs in ordermidiout = MIDI4x4

The numbers on the left are not part of it. 0 1 2 3 are ALSA's own port numbers: they count from zero and shift as gear is plugged in, so nothing in the config refers to them. The :2 in MIDI4x4:2 is a different thing again — the second input this device offers, counted down the indented lines. You only need that form when the port names themselves don't tell two devices apart.

aconnect -l shows the same list with what is wired to what, including the sequencer's own GroovixBox ports while it is running — the way to check a patch from outside the instrument. amidi -l lists the hardware instead, by card, which is useful when a device is plugged in but no ALSA client appeared for it.

The value is a CC number 0–127, or off. After it, full (the default) sweeps 0–127 across the travel and center holds CC 64 in a small detent in the middle, for pan-like controls. # or ; starts a comment. A bad line is reported with its line number, and the lines before it still apply.

Voice lists

A preset pad sends a voice, not a number. Which voice is a row of that device’s own list, read at startup from a CSV — the maker publishes one in its Data List.

Two files, in the config directory. voices.conf says which list belongs to which device:

sx920.device = PSR-SX920            # part of the name, matched as midiout and p1-p8 are
sx920.file   = voices/psr-sx-920.csv

Both are values, so a device name can carry spaces, slashes and punctuation without having to survive being a filename or a config key. The id on the left is yours and only pairs the two lines.

The CSV is the maker’s file, pasted in whole. It needs a header row and nothing else: the reader finds MSB, LSB, PC and Name by name, in any order, among any other columns, so another maker’s layout needs no configuring.

MSB#,LSB#,PC#,Name,,,,Type
104,21,1,CFX ConcertGrand,,,,S.Art
104,10,1,CFX StageGrand,,,,S.Art

Those two rows are why this exists: same bank, same program, different LSB. A PSR-SX920’s 1,650 voices put seven grand pianos on one MSB and one PC, told apart by the LSB alone.

  • Programs count from 1, the way every printed list prints them. A 0 in that column refuses the file rather than putting every voice in it one place out.
  • A row that isn’t a voice is skipped — MSB, LSB and PC must all be numbers — which is how a heading or the copyright line at the foot of a list looks after itself. The count is reported.
  • A bad list is refused whole, unlike controls.conf where a bad line can be stepped over. A voice list is positional: one dropped row shifts every slot after it and quietly changes what saved projects play.
  • Paths stay inside the config directory. The file says which list to read, not where on the disk to read from.
  • No list, no problem. A device nothing is said about plays the built-in General MIDI list: bank 0, 128 programs. There is no other path — every preset, always, is a row of some table.

Which list a port plays from follows what is on that port, resolved as the ports are wired, so a REFRESH that moves a synth to another port takes its voices with it. Startup says what each one ended up with, and --midi-log names the voice as it goes out:

voices: P1 Yamaha PSR-SX920 - 1650 from voices/psr-sx-920.csv (2 rows skipped)
MIDI P1 ch1  bank MSB (CC  0) 104
MIDI P1 ch1  bank LSB (CC 32)  21
MIDI P1 ch1  program   0  bank 104:21  preset 1.01  CFX ConcertGrand

Treat a voice list as part of the rig, versioned beside controls.conf. Slots are positions in it, so swapping in a revised file with voices inserted changes what every saved project plays.

LED colours

Slots and pages

Project, pattern and preset pads, and the page maps on the buttons, share one colour code.

  • Selected / shown
  • Has data
  • Empty
  • Off: doesn’t exist
  • Built in: read-only

Amber is the one that behaves differently. It marks the built-in pattern bank — patterns 33–64, the bottom half of Pattern mode’s grid: those patterns ship with the instrument, play as soon as you tap them, and cannot be edited or cleared. R6 copies one up to rows 1–4 to make it yours.

While R6 Duplicate is held, the picked source pad turns white. Red belongs to markers rather than to tracks: the pattern's last step in Note mode, the Record button, and the playhead while recording. No track is red, so none of those can be mistaken for one.

Track colours

Tracks use eight colours, repeated on every track page: tracks 9–16 use the same colours as 1–8, and so on to 64.

  • B1 peach
  • B2 orange
  • B3 yellow
  • B4 green
  • B5 cyan
  • B6 blue
  • B7 purple
  • B8 pink

Modes

Each mode has its own page, with the buttons and pads it uses.

  • R1 NoteSteps and the scale keyboard, chords, keyboard octave.
  • SHIFT + R1 ScaleRoot note and scale for the Note mode keyboard.
  • R2 Step parametersPer-step velocity and gate, 16 levels each.
  • SHIFT + R2 PresetChoose the sound preset for the selected track.
  • R3 ProbabilityThe chance each step plays, 6% to 100%.
  • SHIFT + R3 Global settingsThe tempo, and each track’s MIDI channel.
  • R4 PatternWhich pattern each track plays, and pattern/track pages.
  • SHIFT + R4 ScenesWhich tracks are silent in each section, on 32 pads.
  • SHIFT + R5 ProjectOpen, save and page through project slots.
  • SHIFT + R8 SongThe scenes in the order they play, four bars a step.

Clear, Duplicate, Record, Play

R5 Clear

Hold it and tap pads. What gets cleared depends on the mode: a step in Note mode, a pattern in Pattern mode, a project in Project mode. Preset mode has nothing to clear — a preset is a number, not something the sequencer keeps.

R6 Duplicate

  1. Hold R6.
  2. Tap the source pad; it turns white.
  3. Tap one or more destination pads. You can change page in between.
  4. Release R6.

Copying an empty slot onto a full one empties it.

R7 Record

Turns recording on or off, whether or not the sequencer is playing. It only has an effect while playing, when pressing note pads in Note mode — or playing a MIDI keyboard — writes notes into the selected track. While it is on the playhead runs red instead of white, so the grid itself shows that it is listening. See what recording looks like.

R8 Play

Starts playback from step 1, or stops it. Stopping releases every sounding note and resets the playhead.

Pages

The grid shows 8, 32 or 64 of something at a time; pages reach the rest. Patterns need none: a track has 64 and the grid is 64 pads, so Pattern mode shows the whole of a track’s choice at once and its bottom buttons are free to be the tracks, as they are everywhere else.

Simulator

The simulator draws the device in a window. Every button has a key, and the mouse presses pads and moves faders.

All keys, combinations and mouse actions are on the Keyboard shortcuts page, with the device button each key presses.

Status line

The line above the pads shows what the device has no display for:

PRJ 3.08  NOTE     TRK 12  PAT 10  PRE 1.01  STEP 05/32  120 BPM  PLAY REC

Open project, mode, selected track, the pattern and preset it uses, the playhead position on that track, tempo, and transport state.

MIDI

The sequencer's output is eight ALSA sequencer ports named P1–P8, one per MIDI port, under the client GroovixBox. Every port also carries MIDI clock, 24 per quarter note, with Start when playback begins and Stop when it ends, so external gear follows the tempo. They are wired up at startup: the sequencer looks for a MIDI interface and connects P1 to its first socket, P2 to the second, and so on, which puts a 4×4 interface on P1–P4. It only ever picks a real interface — never the kernel's loopback, never one of its own control surfaces, and it prefers the device with the most inputs, so a 4×4 wins over a keyboard that happens to be plugged in first — and it leaves the ports alone if something has already patched them, so a patch made by hand with aconnect or a patchbay survives. Global settings shows which ports found something, and its refresh pad looks again for anything plugged in since. To see the same thing from outside, aconnect -l lists every port and what it is wired to; finding the names has more. An APC mini mk2 is picked up automatically as the control surface, on its own client GroovixBox Surface.

Only one at a time

A second simulator refuses to start while one is already running: both would answer every press of the same APC and MIDI Mix, and both would write to the same projects.

How to…

Give steps different notes

  1. In Note mode, hold a step pad.
  2. Tap a note pad on the keyboard. Repeat with other steps.

In the simulator, right-click each key to latch it down, then left-click the step. Right-click the keys again to let go. The same trick works for any combination that needs more than one pad at once.

Work on tracks 9–16

  1. In Note mode, hold SHIFT and press B2 (Shift + 2).
  2. Release SHIFT. B1–B8 now select tracks 9–16.

Copy a pattern to another track

  1. Press R4 for Pattern mode, then B1–B8 for the track the pattern is on.
  2. Hold R6 and tap the source pattern.
  3. Still holding R6, press the B button of the other track and tap the destination pad.
  4. Release R6, then tap the destination to make that track play it.

Save the current project as a new copy

  1. Hold SHIFT and press R5. The open project is green.
  2. Hold R6, tap the green slot, then tap an empty slot. Press SHIFT + a B button in between to use another page.
  3. Release R6 and tap the new slot to continue working in the copy.

Give each track its own MIDI channel

  1. Hold SHIFT and press R3, then tap pad 2 of the top row.
  2. Tap a channel on rows 3–4 for the selected track.
  3. Press the next track’s B button — you stay in the mode — and tap its channel. Repeat along the row.
  4. SHIFT + B1–B8 moves on to tracks 9–16 and beyond, as far as 57–64.

Choose a preset for track 5

  1. Press B5, then SHIFT + R2.
  2. Tap a pad, or hold SHIFT (or R2) and press a B button to change page first.

Saving

  • The open project is saved when you open another project and when the simulator quits.
  • On start, the last open project opens again.
  • Files in the data folder: project_NN.gxb, preset_NN.gxb and session.gxb (which project was open).
  • A save can't corrupt what was there. Every write goes to a temporary file and is renamed over the old one only once it is complete, so a power cut during a save leaves the previous version intact.
  • Clearing doesn't delete the file. R5 + a project or preset pad moves it into trash/<date>_<time>/ inside the data folder — trash/2026-09-22_23-32-31/project_07.gxb — so a mistaken Clear can be undone by copying the file back. Clears in the same second share a folder and never overwrite each other. Copying an empty slot over a full one empties it, and that is kept too. Nothing empties the trash, so it is worth a look now and again.

Current limitations

What the simulator build doesn’t do yet.

  • Rolls and arpeggios are even. A ratchet repeats a step up to eight times at equal spacing, and the arpeggiator plays a chord at one rate; neither can accent, swing or vary within itself.
  • Swing is one setting for the whole project, in Global settings, not per track or per pattern. Per-step micro-timing is what moves a single hit.
  • MIDI in is notes, the transport and the clock. A keyboard plays and records into the selected track, Start and Stop work, and the box can follow an outside clock. What still doesn't come in: CC, and any way to send what arrives to more than the selected track.
  • No Song Position Pointer, in or out. Playback always starts at step 1, so Continue is treated as Start when following, and gear following us starts from its own beginning.
  • No Song Position Pointer. Gear following the clock starts from its own beginning, since playback always starts at step 1.
  • A preset holds nothing of the sequencer’s own. It names a voice in the gear and sends Bank Select and Program Change for it, which is what external gear wants, but there is no patch to save until there is a sound engine with parameters to put in one.
  • Chords are capped at 4 notes per step. It is one constant in the engine, but raising it grows every project file.
  • The faders have no mixing function of their own. They send CC, which a synth may map to level; the sequencer itself has no volume.
  • Part of the mixer has no function yet. The mute row mutes and solos tracks and the knobs and faders send MIDI CCs, but the A2 row and M1–M3 have nothing on them.
  • CC is send-only. Nothing reads CC in; the last pad of Global settings sends every position out again.
  • Mutes are not saved. They belong to the session, so opening another project clears them.
  • No undo. Clear acts immediately, including on projects — though on a project or preset the file is moved to the trash folder rather than deleted, so it can be fetched back by hand. Clearing a step or a pattern is gone for good.
  • Page position is only shown while holding SHIFT (or R2 in Preset mode) — unless a page panel is attached, which shows all four kinds at once and never needs a modifier.
  • Projects only partly move to smaller builds. A project with more tracks than the build opens with its first tracks (64 in the simulator, 16 in the MCU default) and drops the rest when it next saves. A project with more patterns or steps than the build still won’t open.
  • A built-in pattern does not set the track’s preset. The bank on patterns 33–64 plays notes out of whatever channel, port and voice the track already has, so a drum pattern only sounds like drums once you have put a kit on that track yourself. Which voice each role should call up is device-specific, and waits on a preset document.
